**公开语料（与跑分同仓，可自行核对）**

| 材料 | 链接 | 谁在读 |
|---|---|---|
| 源手册正文（约 4997 字，按章排列） | [源手册正文](../对比测试_澄海手册_知识库.md#源手册正文) | 传统 RAG / LightRAG **条件 B** |
| 已发布问答（103 / 211 条） | [已发布问答](../对比测试_澄海手册_知识库.md#已发布问答) | 三家 **条件 A**；AmendAQ **条件 B** 也只看这一份 |
| 只在整理稿里的拒答句 | [只存在于已发布问答的句子](../对比测试_澄海手册_知识库.md#只存在于已发布问答的句子) | 条件 A 对照系统可见；条件 B 看不到 |
| 题干与标准答案 | [对比测试_澄海手册_题目.md](../对比测试_澄海手册_题目.md) | 判分依据；下文逐题表第一列即这些题干 |

完整索引见 [测试知识库原文](../对比测试_澄海手册_知识库.md) 文首说明。

- **语料**：虚构《澄海精密员工手册》，上表两份正文来自同一对照包。跑了两档：**103 条已发布问答 / 48 题**；**211 条 / 80 题**（含 **30 道**跨条：原 10 道必须同时跨两条以上 AQ 的题）。  
- **生成模型**：三家统一 `Qwen3.6`（AmendAQ 已支持接口）。  
- **判分**：程序核对义务、数字、拒答、不编造；不让模型自评。  
- **AmendAQ**：表中 **AmendAQ** 列；始终用**整理后的已发布词条**（条件 B 也不改语料）。  
- **传统 RAG**：500 字切分、重叠 80；jieba BM25 + `BAAI/bge-large-zh-v1.5` + RRF + `bge-reranker-large` 取 **Top 5** 段。  
- **LightRAG**：1.5.8，默认 `mix` 查询；嵌入/重排与传统管线同一对。  
- **GraphRAG**：未纳入（建索引贵，且项目目前基本是维护模式）。  
- **两种条件**  
  - **条件 A**：三家都看**已发布问答**（公平比准确率）。  
  - **条件 B**：传统 RAG 与 LightRAG 看**源手册正文**；AmendAQ 仍看词条。源手册不含运营写的「手册没有这条规定」句。

整理稿里的拒答条（如住房补贴、靠窗工位）在条件 A 里对照系统也能看到；条件 B 看不到。

## 四、对照表分析

无全面优胜者，每种方案都有其优势场景。

- **103 条 / 48 题 / 条件 A**：LightRAG **48/48**；AmendAQ 与传统 RAG **46/48**。  
- **211 条 / 80 题 / 条件 A**（生成 **Qwen3.6**）：AmendAQ **74/80**，传统 RAG **74/80**，LightRAG **72/80**。  
- **条件 B**：AmendAQ **74/80**，传统 RAG **73/80**，LightRAG **74/80**。

**按类型（211 条 · 80 题 · 条件 A）**

- 义务对错（30 题）：AmendAQ **29/30**，传统 RAG **28/30**，LightRAG **25/30**。  
- 数字（25 题）：LightRAG **24/25**，AmendAQ **22/25**，传统 RAG **21/25**。  
- 拒答（8 题）：传统 RAG 与 LightRAG **8/8**，AmendAQ **6/8**。  
- 不编造（8 题）：AmendAQ 与传统 RAG **8/8**，LightRAG **6/8**。  
- 跨条（30 题）：AmendAQ 条件 A/B **29/30**；传统 RAG 条件 A/B **27/30**；LightRAG 条件 A/B **27/30**（新 20 道各 **18/20**）。

**时间（211 条 · 80 题 · 生成 Qwen3.6）**

对照里和「时间」相关的量分三类：建索引、答一题、累计 token。下文数字来自 [对比测试_澄海手册_200条.md](../对比测试_澄海手册_200条.md) 同一次 `compare200` 跑分。

**答一题（wall-clock 中位数）**

|  | 条件 A | 条件 B |
|---|---|---|
| 传统 RAG | **8.1s**（检索中位 **4.8s** + 生成中位 **3.0s**） | **5.7s**（检索 **2.7s** + 生成 **2.8s**） |
| AmendAQ | **22.4s**（未拆分检索/生成） | 同左（语料不变） |
| LightRAG | **33.9s** | **26.7s** |

其中 **跨条 20 道**子集的中位数（条件 A）：传统 **8.7s**，AmendAQ **26.2s**，LightRAG **36.8s**。

**建模次数（条件 A，80 题合计）**：传统 RAG **80** 次（一题一次生成）；LightRAG **160** 次（一题两次，与 48 题档相同口径）；AmendAQ **257** 次（一题常含分批读标题 + 勾选 + 作答，折合约 **3.2 次/题**）。

**索引（建库，不是每题摊销）**

| 系统 | 条件 A | 条件 B |
|---|---|---|
| AmendAQ | **约 0.02s**（对照里为载入已发布 AQ，无向量重建） | 同左 |
| 传统 RAG | **3.4s**（加载 `compare200/cache/` 向量） | **3.1s** |
| LightRAG | **903s**，建图阶段模型调用 **34** 次 | **644s**，**22** 次 |

LightRAG 的索引时间是本机 `data/eval/compare200/lightrag/` 下**首次**写入图谱时的记录；之后 `resume` 会复用目录，表上的秒数不变。

**输入 token（条件 A，80 题合计）**：传统 **15.2 万**，AmendAQ **123.8 万**，LightRAG **133.9 万**。AmendAQ 每条题会带上多批标题与已勾选 AQ 正文，因此 prompt 累计高于「只送 Top-5 段」的传统 RAG。

**AmendAQ 在 211 条上丢的 5 分（条件 A）**：「实习生要用正式员工的账号看客户资料，用完就退出。可以共用吗？」（未写全实习生）、「今天下午室外作业，气温到了 37℃。休息要怎么安排？」（未写 **35℃** 起算）、「一名固定期限员工已经在职 2 个月零 10 天。他现在有几天年假？」（2 个月零 10 天应是 **2 天** 年假）、「公司每个月的住房补贴是多少钱？」；「靠窗的工位是按职级分，还是按入职年限分？」（拒答句式未命中判分规则）。

**语料更新（未列入上表）**：AmendAQ 改一条已发布 AQ 后发布即可；传统 RAG、LightRAG 若改源手册正文，切片或图谱需按各自管线重建或更新，本对照未单独记录这部分耗时。

## 五、什么时候可以考虑 AmendAQ

| 场景 | 更合适的路径 |
|---|---|
| 一本制度 / 办事指南，几十～两百条，会经常改某一条 | **AmendAQ**：发布即生效，按编号取正文 |
| 一题要同时用上两条以上规定，漏一条即错 | **AmendAQ**：30 道跨条合计条件 A/B **29/30**（本节附录有逐题表） |
| 仍是原始长文档，先要搜到一段 | **传统 RAG**（本测更快、更省 token） |
| 要图索引式综合、能接受建图成本 | **LightRAG** 等（103 条条件 A 曾全对） |
| 多库全文搜词 | 三者都不是；AmendAQ 一次只读一本已选库 |

这不是公开基准冠军榜，只锁了一条传统管线和 LightRAG 1.5.8；嵌入/重排 revision 见仓库 `docs/对比测试_澄海手册*.md`。
