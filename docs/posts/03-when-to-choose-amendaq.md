# 同题对照之后，有些场景可以选择 AmendAQ

> 系列：AmendAQ, a better RAG?（3/3）
>
> 上一篇：[AmendAQ 在 mycs 里是一本可以改的问答](./02-what-amendaq-is.md)

可以选择。场景要收窄：一次一本制度，几十到两百条可以单独改的问答，用户问的是义务、数字、拒答，或者要把两三条规定合在一起。在这个范围里，AmendAQ 和一条认真实现的传统 RAG、以及 LightRAG，准确率在同一档。AmendAQ 多出来的是发布前就把话说死，以及改一条不用重建索引。

它没有在对照里全面更高。传统 RAG 更快，输入 token 更少。库一长，AmendAQ 的拒答会松。下面按两次实测写，先写结论能用在哪，再写它输在哪。

这不是公开基准上的冠军榜。对照只锁了一条传统管线，外加 LightRAG 1.5.8。GraphRAG 没有跑：整库抽取贵，而且那个项目目前基本是维护模式。

## 怎么比才算同一道题

语料是一本虚构的《澄海精密员工手册》。生成模型锁成 `Qwen3.6`，三家走 mycs 已经支持的同一个接口。判分是程序核对答案里的义务、数字、拒答和不编造，不让模型给自己打分。

两种条件都跑。

- **条件 A。** 三家都只看已发布问答。这是准确率的公平对照。
- **条件 B。** 传统 RAG 和 LightRAG 看源手册正文，AmendAQ 仍看整理后的词条。源手册里没有那些「手册没有这条规定」。这一条件看的是：不先整理成 AQ、直接切原文，会怎样。

传统管线是固定 500 字切分、重叠 80 字，jieba 搜索模式 BM25 加稠密向量，RRF 之后重排取前 5 段。嵌入是 `BAAI/bge-large-zh-v1.5`（`79e7739b6ab944e86d6171e44d24c997fc1e0116`），重排是 `BAAI/bge-reranker-large`（`55611d7bca2a7133960a6d3b71e083071bbfc312`）。LightRAG 用它自己的默认查询 `mix`，嵌入和重排是同一对。嵌入和重排只出现在对照系统里。

题分五类：单点查找、义务对错、数字、拒答、不编造。后一次又加了 10 道必须同时用上两条以上 AQ 的复杂题，只命中其中一条算没答全。

48 题说明小库上三家都能用。真正拉开维护形态的是下一档：条目加倍，并加入必须跨条目的题。

## 211 条问答，60 题

这一轮已发布问答 211 条，源手册 4997 字，题目 60。AmendAQ 每批送 200 条标题，两批都扫完。传统管线的向量用了本次目录里的缓存，表上的索引耗时是加载缓存的时间。LightRAG 的索引耗时仍是第一次抽取图谱的时间。

## 表里没有量到的那件事

两次对照的手册都是冻住的。它量准确率、延迟、token 和建索引的生成次数。它不量「下周二上限从 20 改成 30」。

AmendAQ 的索引耗时是 0 秒、索引生成 0 次，因为发布本身就是索引：人改完那一条，下一次勾选读到的就是新标题和新摘要。传统 RAG 在这套题上重建一次向量只要几秒，缓存命中之后不到 1 秒。贵的不是这一本 5000 字的手册，而是改完之后要确认没有旧块还留在前 5 段里。LightRAG 这一本要 644 到 903 秒，外加 22 到 34 次抽取，改一条制度意味着这趟抽取要不要重跑。

延迟站在传统 RAG 一边。211 条、条件 A，单题中位 7.6 秒，AmendAQ 21.2 秒，LightRAG 33.5 秒。AmendAQ 的输入 token 是 91.7 万，传统 RAG 是 11.3 万。差别来自每题都把 211 条标题送进去，而且 60 题一共调用了 185 次生成；传统 RAG 一题一次，只把重排后的前 5 段送进去。

所以「更好」如果指更快、更省，答案是传统 RAG。如果指改一条制度的动作是打开那一条再发布，答案是 AmendAQ。准确率在这 60 题上没有给出第三种答案：三家都在 54 到 56 之间。

## 什么场景选哪条

| 材料长什么样 | 更合适的做法 |
|---|---|
| 一本制度或办事指南，几十到两百条，运营会改其中某一条的数字或义务 | AmendAQ。发布即生效，提问按编号取 |
| 用户的一句话里叠着两三条规定，漏一条就算错 | AmendAQ。这 10 道是 10/10 |
| 原文还是纪要、聊天、长文档，没人把它收成问答，先要搜到一段 | 传统 RAG。这套题上它最快 |
| 要做主题级综合，能接受建图的时间和抽取次数 | LightRAG 这一类。103 条那轮它在条件 A 全对 |
| 在很多份文档里找提到某个词的那一份 | 不是 AmendAQ。它一次只读一本已选定的库 |

AmendAQ 现在的洞也写在表里。211 条时，住房补贴和靠窗工位没有守住拒答；共用账号、高温休息、固定期限年假没答全。条目再往上加，每题通读标题的 token 和延迟会继续涨。短名单式的向量检索当时没接进主路径，就是为了避免「像」代替「这一条能回答」。库如果远大于两百条，该先拆库，而不是把通读标题当成搜索引擎。
