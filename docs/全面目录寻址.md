# 全面目录寻址（LLM-only）

**产品策略**：召回只靠 **Wiki 目录 + LLM 分批判断**，不用向量、不用词元加权 `kg_search` 当裁判。

## 两种目录形态（`kg_document.catalog_mode`）

| `catalog_mode` | 适用 | 召回 |
|----------------|------|------|
| `hierarchical`（默认） | 编号员工手册 | 下面「章 → 子层 BFS」 |
| `flat_faq` | 好势类 FAQ（`document_id=faq` 等） | **全叶标题分批勾选**，不下钻章；trace 步 `faq_title_batch` |

入口：`agent/toc_recall_phase.py` 按 `KnowledgeService.document_catalog_mode` 分支。

## 流程（`hierarchical`）

0. **题目拆分（可选）**：用户一次输入多道独立问题时，先用**独立 prompt**拆成子问题；每道子问题再走下面 1–4 步（不扩大 comprehensive 的 composite 补丁）。
1. **一级目录（章）**：按 `MYCS_TOC_BATCH_SIZE` 分批把章标题交给 LLM；**必须消费完全部批次**（LLM 若 `done/stop` 且还有后续批，系统强制当作 `continue`）。列举类问法（如「有哪些」）**不再**由规则跳过 L1，仅加强 prompt（`enumerative_query`）。
2. **子目录**：对每个入选章，列出其**全部直接子节点**，再分批交 LLM 勾选；同样 **不得在未看完所有批前结束**；未选中的中间层若下面还有层，继续 BFS 展开。**子层 0 选不灌整章叶**。
3. **叶节点**：汇总 LLM 选中的 `leaf`；对每条 `section_ref` 调用 `graph.entity.by_section` 拉实体正文（工具轮次上限 `MYCS_MAX_TOOL_ROUNDS`，默认 128）。L1 0 章 / 叶层 0 叶时不做「全库兜底」，可走 Plan 补洞（`loop` 既有逻辑）。
4. **作答**：Compose 只依据已拉取的叶/实体；Verify 对照节号与正文。

## 代码入口

| 模块 | 作用 |
|------|------|
| `planning/flat_faq.py` | 扁平 FAQ 标题分批 |
| `planning/comprehensive_toc.py` | L1/L2+ 强制分批遍历 |
| `agent/toc_recall_phase.py` | 按 `catalog_mode` 选 flat / comprehensive |
| `agent/toc_comprehensive_phase.py` | comprehensive 接入与 trace |
| `agent/loop.py` | `graph_qa` 主链，不再 `toc_drill` 单路径、不再 `graph.entity.search` |
| `llm/openai_compat.py` | `review_toc_catalog_batch`、`review_toc_children_batch` |

## 耗时与准确度

- 设计目标：**宁可极慢也要扫全目录批次的语义空间**，用 prompt / 换模型调准确度，**不靠隐藏打分规则**。
- Trace：`toc_catalog_batch`、`toc_children_batch`、`toc_comprehensive` 可看每批 LLM 决策。

## 环境变量

```bash
MYCS_TOC_BATCH_SIZE=8    # 每批章/节条数，越小调用越多
MYCS_MAX_TOOL_ROUNDS=128 # 单问最多 by_section 次数
```
